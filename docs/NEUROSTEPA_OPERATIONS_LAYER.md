# NEUROSTEPA_OPERATIONS_LAYER.md

Операционный слой НейроСтёпы для Путеводителя: практический план внедрения.

## 1) Продуктовая идея

**НейроСтёпа = AI Operations Layer** поверх Путеводителя:
- помогает участникам и родителям,
- ускоряет работу вожатых и старших,
- усиливает SMM и воронку набора,
- снижает хаос и нагрузку на ручные процессы.

Цель: не «ещё один бот», а системный контур поддержки принятия решений и коммуникации.

---

## 2) Роли и сценарии

## 2.1 Participant (участник)
- Подсказки по маршруту значков и уровней.
- Помощь в формулировке плана и рефлексии.
- Объяснение «что делать дальше» простым языком.

**KPI:** рост завершений маршрутов, снижение «застреваний» в прогрессе.

## 2.2 Parent (родитель)
- Быстрые FAQ-ответы по оргвопросам.
- Разъяснение образовательной ценности без перегруза.
- Мягкая маршрутизация к организаторам для переменных условий.

**KPI:** меньше повторяющихся вопросов, выше доверие, выше конверсия в диалог.

## 2.3 Counselor / Educator (вожатый/педагог)
- Черновики решений по заявкам на апрув.
- Подсветка рисков (формальные/слабые подтверждения).
- Помощь в формулировке обратной связи детям.

**KPI:** быстрее обработка inbox, выше качество обратной связи.

## 2.4 Shift leader / Camp director
- Сводка «что горит» (очереди, проблемные точки, статусы).
- Помощь с орг-коммуникациями и внутренними анонсами.
- Операционный ко-пилот для смены.

**KPI:** время реакции на инциденты, прозрачность статусов.

## 2.5 SMM/бренд-контур
- Пост/коммент/FAQ/CTA-конвейер в едином тоне.
- Дистилляция длинных материалов в короткие инсайты.
- Поддержка добора мест без «давящего маркетинга».

**KPI:** replies, диалоги, заявки, заполнение смены.

---

## 3) Фазы внедрения

## Фаза O1 (быстрый запуск, 7–10 дней)
- Включить НейроСтёпу как единый контур ответов (SMM + parent FAQ).
- Зафиксировать правила тона, safety, эскалации.
- Подключить ежедневный операционный цикл (чеклисты уже есть в docs/smm).

**Артефакты:**
- FAQ, decision tree, objections handling, daily checklist, execution map.

## Фаза O2 (staff-операции, 2–3 недели)
- Добавить AI-подсказки для апрувов/модерации.
- Шаблоны обратной связи для вожатых.
- Внутренние «сводки смены» для старших.

## Фаза O3 (встраивание в ЛК/механики, 3–5 недель)
- Контекстные подсказки внутри ЛК по ролям.
- Поддержка маршрутов значков и планов развития.
- Стыковка с Council / Squad / Engine механиками.

## Фаза O4 (масштаб и аналитика)
- Метрики качества ответов и конверсии.
- A/B формулировок.
- Политики качества и периодические аудиты фактов.

---

## 4) Product guardrails (обязательно)

- Финальные цены/условия подтверждают организаторы.
- В переменных вопросах — не выдумывать, а эскалировать.
- В обсуждениях: отвечать по теме лагеря, оффтоп — мягкий редирект/NO_REPLY.
- Один триггер = один ответ (анти-дубли, анти-self-reply).

---

## 5) Что уже готово (база)

Готова сильная операционная база в `docs/smm/`:
- playbook, voice, comment engine,
- parent FAQ + decision tree,
- style distillation + insight libraries,
- objection handling + last-6 conversion pack,
- execution map + daily/weekly runbooks + README index.

Это позволяет запускать O1 сразу, без ожидания большой разработки.

---

## 6) Следующий практический шаг

1. Утвердить этот документ как целевую модель.
2. Выбрать 1 sprint-фокус: **O1** (операционка) или **M1** (Q1 механик: scoped engines).
3. Запустить недельный цикл с измерением KPI.

Рекомендуемый старт: **O1 + M1 параллельно**
- O1 даёт быстрый бизнес-эффект (коммуникации и набор),
- M1 закрывает архитектурный долг продукта.
