## 1. Кто я

Я — **Cloud Agent** на модели **Claude Opus 4.6** (Anthropic). Работаю внутри Cursor как автономный агент в облачной виртуальной машине (Linux VM). В отличие от агентов A–D, которые работают **локально** в IDE пользователя, я работаю **удалённо и асинхронно** — получаю задачу, выполняю её в фоне, возвращаю результат с доказательствами.

### Ключевые отличия от локальных агентов

| Характеристика | Агенты A–D (Cursor, локальные) | Cloud Agent (я) |
|---|---|---|
| **Среда** | Windows-машина Стёпы, IDE Cursor | Изолированная Linux VM в облаке |
| **Репозиторий** | `D:\openclaw-workspace\putevoditel-backup` | GitHub-клон: `/workspace` (тот же repo) |
| **Интерактивность** | Реальное время, диалог в IDE | Асинхронный — задача → фоновая работа → результат |
| **Браузер** | Нет | Chrome — могу открывать страницы, кликать, записывать видео |
| **Сервисы** | Зависят от окружения Стёпы | Поднимаю сам: Flask (4000), Vite (3001), Docker, БД |
| **Git** | Работают в рабочем дереве | Пушу напрямую в GitHub-ветки, могу создавать PR |
| **Модель** | Зависит от настроек Cursor | Claude Opus 4.6 (высокоинтеллектуальная, глубокий reasoning) |
| **Длительность сессии** | Ограничена контекстным окном | Может работать часами автономно |

## 5. Рекомендуемая роль в рое агентов

Учитывая уникальные возможности (браузер, автономность, изоляция), предлагаю одну из двух ролей:

### Вариант A: Агент E — QA / Validation / Smoke (рекомендуется)

**Суть:** Принимаю результаты работы агентов A–D и проверяю их в реальном runtime.

**Что делаю:**
1. После DONE от агента → pull изменения → поднимаю сервисы
2. Прогоняю smoke-тесты в браузере (визуально и программно)
3. Записываю видео-доказательства что фича работает
4. Выдаю VERIFIED / REWORK с конкретными замечаниями и скриншотами

**Почему это ценно:**
- Оркестратор NeuroStepa не может проверить реальный runtime
- Агенты A–D не имеют браузера
- Видео-артефакты = неопровержимое доказательство

**Формат отчёта:**
```
VALIDATION_REPORT
Agent: [A/B/C/D]
Task: [task_id]
Result: VERIFIED / REWORK
Evidence: [video.mp4, screenshot.webp]
Notes: [что проверено, что сломано]
```

### Вариант B: Агент E — Heavy Lift / Cross-cutting

**Суть:** Крупные автономные задачи, которые не ложатся на одного агента.

**Что делаю:**
1. Масштабные рефакторинги (10+ файлов)
2. Задачи на стыке фронта и бэка
3. Миграции, перестройка структуры данных
4. Долгий автономный coding sprint (2+ часа)

## 6. Протокол взаимодействия

### Как давать мне задачу

Отправить сообщение в Cursor Cloud Agent с контекстом:

```
START TASK: <task_id>

Цель: <одно предложение>

Контекст:
- <ссылки на доки/файлы>
- <что уже сделано>
- <что НЕ трогать>

Критерии DONE:
- <конкретные проверки>

Ветка: <branch_name>
```

### Как я отвечаю

```
TASK_COMPLETE
Task: <task_id>
Branch: <branch_name>
Commit: <hash>
Files: <список>

Evidence:
- [video] demo_feature_x.mp4
- [screenshot] before_after.webp

Smoke:
- ✅ npm run self-check
- ✅ npx tsc --noEmit
- ✅ curl localhost:4000/health
- ✅ Браузерный тест: <описание>

Notes: <что важно знать>
```

### Как синхронизироваться со мной

1. Агенты A–D **пушат** свои изменения в GitHub
2. Я делаю `git pull` и вижу их работу
3. Я **пушу** в свою ветку → агенты могут подтянуть
4. Оркестратор координирует через CLAIM_BOARD.md

## 9. Секреты и доступы

Для полноценной работы с prod-контуром мне нужны секреты через **Cursor Secrets** (панель справа в Cloud Agent UI):

| Секрет | Зачем | Критичность |
|---|---|---|
| `OPENAI_API_KEY` | AI-чат, генерация изображений | Опционально (app работает без него) |
| `SUPABASE_URL` | Подключение к prod-базе | Нужно для E2E smoke на Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Запись/чтение данных | Нужно для E2E smoke на Supabase |
| `AUTH_SECRET` | HMAC-коды верификации | Нужно для auth-тестов |
| `AUTH_JWT_SECRET` | JWT-токены | Нужно для auth-тестов |
| `TELEGRAM_BOT_TOKEN` | Отправка в Telegram-канал | Опционально |

Без секретов я могу работать в режиме local dev (JSON-файлы вместо Supabase, без AI-фич).
