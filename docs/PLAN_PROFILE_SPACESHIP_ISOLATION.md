# План: изоляция разработки «Кабина космического корабля» на отдельном сервере

Цель: вся разработка нового дизайна личного кабинета («пульт» / «кабина») ведётся только в контексте **нашего сервера** (profile-desktop). Основное приложение (index.html, порт 3009) не меняется по дизайну профиля. Новая версия кабины должна **полностью сохранять все элементы и функции** — никакие кнопки, подписи, прогресс-бары и блоки интерфейса не исчезают.

**Связанные документы:**
- [PROFILE_CABIN_AUDIT.md](PROFILE_CABIN_AUDIT.md) — полный аудит элементов и функций ЛК (откуда данные, как реализовано, критичные id).
- [PROFILE_CABIN_COCKPIT_SPEC.md](PROFILE_CABIN_COCKPIT_SPEC.md) — **спека кабины v2**: нижняя консоль (пульт), маппинг кнопок, UX-модель, этапы A/B/C, Definition of Done. Основной документ для реализации «кабины космического корабля».
- [PROFILE_CABIN_SERVER_SETUP.md](PROFILE_CABIN_SERVER_SETUP.md) — **пересборка и запуск** сервера кабины после глобальных обновлений (backend, Telegram, AuthProvider).
- [agent.md](../agent.md) — точка входа для агента, ROADMAP, Memory Bank, верификация.
- Планы десктопного layout (например план «Desktop Profile Layout Plan» / spaceship layout) — куда расставлять блоки.

---

## 1. Текущее состояние

- **Основной сайт:** `npx vite --port 3009 --host` → открывается `index.html` → загружается `main.tsx` → приложение с главной, категориями, профилем.
- **Наш сервер (кабина):** `npm run dev:profile-desktop` (порт 3010) → открывается `profile-desktop.html` → загружается `main.tsx` → то же приложение, но с `window.__INITIAL_VIEW__ = 'profile'`, поэтому сразу показывается личный кабинет.

Проблема: один и тот же код (в т.ч. `ProfileView.tsx`, `profile-view.css`). Любое изменение в них влияет и на основной сайт, и на «кабину». Нужно, чтобы **все изменения дизайна кабины были только у нас**.

---

## 2. Подход: отдельная точка входа + отдельный CSS

Идея: на «нашем» сервере загружать **другой entry point** и **отдельный файл стилей** только для кабины. Основной код (`ProfileView.tsx`, `profile-view.css`) не трогаем для дизайна; весь новый layout — в новых файлах, подключаемых только при открытии profile-desktop.

### 2.1 Отдельный entry point для кабины

- Создать **`src/main-profile-desktop.tsx`** (аналог `main.tsx`):
  - Те же провайдеры: `ErrorBoundary`, `ProgressProvider`, `TeamProvider`, `HintOverlayProvider`.
  - Рендерить тот же `<App />`, но обёрнутый в контейнер с классом-маркером:
    - например `<div className="profile-spaceship-root" data-profile-mode="spaceship">` вокруг `<App />`.
  - Подключить **только здесь** стили кабины: `import '../styles/profile-view-spaceship.css'`.
- В **`profile-desktop.html`** заменить загрузку скрипта:
  - было: `src="/src/main.tsx"`
  - станет: `src="/src/main-profile-desktop.tsx"`
- Оставить в `profile-desktop.html` установку `window.__INITIAL_VIEW__ = 'profile'`, чтобы приложение сразу открывалось в профиле.

Итог: при открытии **только** profile-desktop загружаются `main-profile-desktop.tsx` и `profile-view-spaceship.css`. При открытии index.html загружаются `main.tsx` и общие стили — кабинные стили не подключаются.

### 2.2 Отдельный файл стилей кабины

- Создать **`src/styles/profile-view-spaceship.css`**.
- Все селекторы в нём должны быть в контексте корня кабины, например:
  - `.profile-spaceship-root .profile-view { ... }`
  - `.profile-spaceship-root .profile-view-content-wrapper { ... }`
  - и т.д.
- В этом файле — **весь** новый layout «пульта»: сетка, колонки, расположение блоков (верхняя полоса, паспорт слева, дашборды справа, шеринг в ряд и т.д.) по плану десктопного layout.
- Файл **нигде не импортировать**, кроме `main-profile-desktop.tsx`.

Итог: все визуальные и вёрсточные изменения «кабины» делаются только в `profile-view-spaceship.css`. Основной `profile-view.css` и остальные стили для основного сайта не меняются.

### 2.3 Минимальные правки в общем коде (только структура, без смены дизайна)

Чтобы кабинные стили могли удобно расставлять блоки (grid/flex по зонам), в **`ProfileView.tsx`** можно один раз добавить обёртки с классами (как в плане desktop layout):

- Обёртка для кнопок «Назад / Подсказки / Редактировать» → класс типа `profile-view-top-bar`.
- Обёртка для блока «Прогресс хранится…» и кнопок бэкапа → `profile-view-backup-strip`.
- Обёртка для паспорта (аватар + ник + ранг + прогресс-бар) и редактора → `profile-view-passport-column`.
- Обёртка для списка дашбордов (Инспектор, 4К, Движок, Совет, Уголок, Дневник, БРО, Штаб) → `profile-view-dashboards-grid`.
- Обёртка для «Пригласить друзей» и «Шеринг достижений» → `profile-view-share-row`.

В **основном** `profile-view.css` для этих обёрток задать нейтральное поведение (например, `display: block` без изменения текущего вида). Тогда основной сайт сохраняет текущий вид. В `profile-view-spaceship.css` для `.profile-spaceship-root` задать нужные grid/flex и расположение этих блоков — так весь новый дизайн остаётся только на нашем сервере.

## 3. Где что менять (сводка)

| Что | Где менять | Используется |
|-----|------------|--------------|
| Логика, данные, компоненты профиля | Как сейчас в `ProfileView.tsx`, провайдеры, App | Везде (основной сайт + кабина) |
| Текущий вид профиля (мобильный/текущий) | `src/styles/profile-view.css` | Основной сайт + кабина (базовый вид) |
| Новый layout «кабина» (пульт, десктоп) | **`src/styles/profile-view-spaceship.css`** | **Только кабина** (profile-desktop) |
| Точка входа кабины | **`src/main-profile-desktop.tsx`** | **Только** при открытии profile-desktop.html |
| Страница кабины | **`profile-desktop.html`** | Наш сервер (3010) или тот же порт 3009 по пути /profile-desktop.html |

Правило: **все правки, относящиеся к новому дизайну «космической кабины», вносятся только в файлы, которые подключаются/используются на нашем сервере:**  
`main-profile-desktop.tsx`, `profile-view-spaceship.css`, при необходимости — только обёртки в `ProfileView.tsx` и нейтральные правила в `profile-view.css`.

## 4. Workflow разработки

1. Запускать **наш** сервер: `npm run dev:profile-desktop` (порт 3010) или один общий `npx vite --port 3009 --host` и открывать **http://localhost:3010/profile-desktop.html** (или 3009/profile-desktop.html).
2. Все правки layout/стилей кабины делать в **`profile-view-spaceship.css`** (и при необходимости в разметке обёрток в `ProfileView.tsx` один раз).
3. Основной сайт (index.html) не трогать; проверять его отдельно при необходимости — там не должен подключаться `profile-view-spaceship.css`.

- **Проверка перед коммитом:** `npm run self-check`; визуальная проверка кабины и основного профиля (ни один элемент из аудита не пропал).

## 6. Чек-лист: новая кабина не теряет элементы и функции

При переносе layout в «пульт» (profile-view-spaceship.css и обёртки) проверять по аудиту [PROFILE_CABIN_AUDIT.md](PROFILE_CABIN_AUDIT.md):

**Верх и навигация**
- [ ] Кнопка «Назад», «Показать подсказки», «Редактировать» на месте и работают.

**Резервная копия**
- [ ] Текст «Прогресс хранится на этом устройстве» и подпись с lastUpdated.
- [ ] Кнопки «Сделать резервную копию» и «Восстановить из файла» (функция импорта через скрытый input).

**Паспорт**
- [ ] Блок с **id="profile-passport-card"** (туториал): аватар, никнейм, ранг, прогресс-бар XP.

**Редактор профиля**
- [ ] При «Редактировать»: поле никнейм, кнопки «Фото» и «Сохранить».

**Дашборды (все 8 блоков)**
- [ ] InspectorDashboard (**id="inspector-dashboard"**).
- [ ] Profile4KDashboard (аналитика 4К).
- [ ] TeamDashboard (**id="team-dashboard"**).
- [ ] CouncilDashboard (скролл к team-dashboard).
- [ ] SquadCornerDashboard (отрядный уголок).
- [ ] RealDiaryDashboard (скролл к inspector-dashboard).
- [ ] BroInitiation.
- [ ] WingDashboard (в т.ч. Архитектор отряда при раскрытии).

**Вкладки и контент**
- [ ] Вкладки «В пути», «Коллекция», «Журнал», «Мастерская» с **id="profile-tab-active"**, **id="profile-tab-collection"**.
- [ ] В пути: планы значков, избранное, строки в пути (звёздочка, удалить, «Составить план», «Подтвердить»).
- [ ] Журнал: список достигнутых, «Отправить в Telegram».
- [ ] Мастерская: при отсутствии доступа — Идеи Сообщества + блок «Мастерская откроется…»; при доступе — Архитектор, Кузница Смыслов, Мои предложения, Идеи Сообщества.

**Шеринг и приглашения**
- [ ] Блок «Пригласить друзей» (текст + кнопка копирования ссылки).
- [ ] Блок **id="profile-share-center"**: тумблер «Скрыть ник», «Создать карточку», превью 9:16 и 16:9, «Поделиться / скачать».

**Чат и модалки**
- [ ] **id="profile-chat-trigger"** (ChatAvatar + ChatBot).
- [ ] Модалки: Rank Up, план значка, инициатива в совет, подтверждение значка (proof) — открываются и закрываются, данные сохраняются.

После каждого этапа вёрстки кабины проходить этот чек-лист, сверяясь с аудитом.

## 7. Шаги внедрения (кратко)

1. Добавить **`src/main-profile-desktop.tsx`**: провайдеры + `<div className="profile-spaceship-root" data-profile-mode="spaceship">` вокруг `<App />` + `import '../styles/profile-view-spaceship.css'`.
2. В **`profile-desktop.html`** заменить скрипт на `src="/src/main-profile-desktop.tsx"`.
3. Создать **`src/styles/profile-view-spaceship.css`** с селекторами от `.profile-spaceship-root` и заготовкой под layout по плану (grid, колонки и т.д.).
4. (Опционально) В **`ProfileView.tsx`** добавить обёртки с классами (`profile-view-top-bar`, `profile-view-backup-strip`, `profile-view-passport-column`, `profile-view-dashboards-grid`, `profile-view-share-row`) и в `profile-view.css` задать им нейтральное отображение.

После этого вся дальнейшая разработка «кабины» ведётся только в контексте нашего сервера и только в указанных файлах.
