# Инструкция: изображения на страницах значков и уровней

Эта инструкция описывает, как добавлять изображения на страницы значка и его подуровней (экран значка и экран уровня), чтобы они отображались в карточке под названием значка.

## Что должно быть на экране

- Экран значка: под иконкой и названием значка появляется крупная карточка‑изображение.
- Экран уровня: под иконкой и названием уровня появляется карточка‑изображение соответствующего уровня.
- Общая информация и критерии остаются ниже, в стандартных блоках.

## Откуда берутся изображения

Изображения берутся из папки `public/Новые значки/` и подгружаются через `getBadgeImagePath` из `src/utils/badgeImages.ts`.

В проекте используются два типа изображений:
- **Обычные (иконки значков и уровней)** — компонент `BadgeIcon` использует `getBadgeImagePath` без `realism`.
- **Реализм (фон/крупная карточка)** — используется `getBadgeImagePath(..., 'realism')`.

Структура для обычных изображений (иконки):

```
public/
└── Новые значки/
    └── [Название категории]/
        └── [Название значка]/
            ├── 1 [название базового уровня].jpg
            ├── 2 [название продвинутого уровня].jpg
            └── 3 [название экспертного уровня].jpg
```

Структура для изображений реализма (фон/карточка):

```
public/
└── Новые значки/
    └── [Название категории]/
        └── [Название значка]/
            └── реализм/
                ├── 1 [название базового уровня].jpg
                ├── 2 [название продвинутого уровня].jpg
                └── 3 [название экспертного уровня].jpg
```

Для одноуровневых значков используется только файл `1 ...jpg` (в нужной папке).
Если нужна иконка и фон — добавляйте файлы и в корень папки значка, и в `реализм/`.

Пример (Валюша):

```
public/Новые значки/За личные достижения/валюша/реализм/
├── 1 валюша.jpg
├── 2 помнящий факты.jpg
└── 3 настоящий валюша.jpg
```

## Как устроены страницы

- Экран значка: `src/views/BadgeView.tsx`
  - Получает изображение через `getBadgeImagePath(..., 'realism')`.
  - Рендерит секцию `.badge-hero-media` под заголовком.
  - Для изображения берется базовый уровень (если значок многоуровневый).

- Экран уровня: `src/views/BadgeLevelView.tsx`
  - Получает изображение через `getBadgeImagePath(..., 'realism')`.
  - Для уровня передаются `levelId` и `levelTitle`, чтобы выбрать файл `2 ...` или `3 ...`.
  - Рендерит ту же секцию `.badge-hero-media`.

- Экран категории: `src/views/CategoryView.tsx`
  - Фон карточки значка берётся через `getBadgeImagePath(..., 'realism')`.
  - Иконка значка рендерится через `BadgeIcon` (обычное изображение без `realism`).

- Иконки значков и уровней: `src/components/BadgeIcon.tsx`
  - Использует `getBadgeImagePath` без `realism`.
  - Ищет файлы в корне папки значка (без `реализм/`).

Стили карточки заданы в `src/styles/badge-view.css`:

```
.badge-hero-media
.badge-hero-media__frame
.badge-hero-media__image
```

Если нужно изменить размеры, рамку или цвет — правьте эти классы.

## Как добавить изображения для другой категории

1. Найдите данные значка в `ai-data/category-[id]/[badge-id].json`.
   - Проверьте `categoryId`, `title`, `levels[].title`.
2. Убедитесь, что категория есть в `categoryFolderMap`:
   - Файл: `src/utils/badgeImages.ts`
   - Пример: `'1': 'За личные достижения'`
   - Если категории нет в маппинге, `getBadgeImagePath` вернет `null` и изображения не покажутся.
3. Проверьте имя папки значка:
   - Функция: `getBadgeFolderName` в `src/utils/badgeImages.ts`
   - Если папка не совпадает с нормализацией (например, особые символы или регистр), добавьте явный маппинг по `badgeId`.
4. Добавьте обычные изображения (иконки) в `public/Новые значки/[Категория]/[Значок]/`:
   - `1 [название базового уровня].jpg`
   - `2 [название продвинутого уровня].jpg` (если есть)
   - `3 [название экспертного уровня].jpg` (если есть)
   - Имена файлов должны быть в нижнем регистре, как их формирует `normalizeFolderName`.
5. Добавьте изображения реализма в `public/Новые значки/[Категория]/[Значок]/реализм/`:
   - `1 [название базового уровня].jpg`
   - `2 [название продвинутого уровня].jpg` (если есть)
   - `3 [название экспертного уровня].jpg` (если есть)
   - Имена файлов должны быть в нижнем регистре, как их формирует `normalizeFolderName`.
6. Проверьте отображение:
   - Откройте страницу значка (должен показываться файл `1 ...`).
   - Перейдите на уровни (должны показываться файлы `2 ...` и `3 ...`).

## Правила именования

- Названия файлов должны соответствовать нормализованным названиям уровней из JSON (нижний регистр, замена `ё` на `е`, удаление спецсимволов).
- Номер уровня в имени файла:
  - `1` — базовый
  - `2` — продвинутый
  - `3` — экспертный
- Для базового уровня имя берётся из `badgeTitle` (с обрезкой по ` или ` и по первой строке).
- Для уровней 2/3 имя берётся из `levels[].title`.
- `getBadgeImagePath` приводит имена к нижнему регистру и заменяет `ё` на `е`, поэтому имена файлов должны строго совпадать с этой нормализацией.
- На GitHub Pages регистр и символы в путях чувствительны — любое несовпадение даст 404.

## Проверка перед деплоем на GitHub Pages

После добавления новых изображений обязательно проверьте, что они правильно копируются при билде:

```bash
# Соберите проект и проверьте изображения
npm run build:verify

# Или только проверка (после билда)
npm run verify-images
```

Проверьте регистр и спецсимволы в именах файлов/папок:

```bash
# Проверка несоответствий имен (регистр, ё/е, спецсимволы)
npm run verify-image-names

# Авто-нормализация имен
npm run normalize-images
```

Если нужно нормализовать имена папок (бейджи/подпапки уровней), запустите отдельно:

```bash
node scripts/normalize-badge-images.mjs --apply --include-dirs
```

Скрипт проверит:
- ✅ Все изображения из `public/Новые значки/За личные достижения` скопированы в `dist/RL-Guide-book/Новые значки/За личные достижения`
- ✅ Количество изображений совпадает
- ✅ Конкретные файлы (например, валюша/реализм/*.jpg) присутствуют в dist

Проверка смотрит `dist/RL-Guide-book/...`, потому что при сборке `public` копируется в эту папку (см. `vite.config.ts`).

**Важно:** Все изображения должны быть закоммичены в Git перед push на GitHub. Проверьте:
```bash
git status public/Новые значки/
```

Если файлы не закоммичены, добавьте их:
```bash
git add public/Новые значки/
git commit -m "Добавлены изображения значков"
```

## Частые проблемы

- **Изображение не показывается**:
  - Проверьте `categoryFolderMap` и `getBadgeFolderName`.
  - Проверьте точное совпадение имени файла с названием уровня.
  - Убедитесь, что файл лежит именно в `реализм/`.
  - Проверьте, что файл скопирован в `dist/RL-Guide-book/` после билда.
  - Убедитесь, что файл закоммичен в Git.
- **Открывается только базовый уровень**:
  - Проверьте, что файл `2 ...` и `3 ...` существуют и соответствуют `levels[].title`.
- **Неверный путь**:
  - Проверьте регистр букв и пробелы в именах папок/файлов.
- **Переименование только регистра на Windows не сработало**:
  - Используйте `git mv` (например, во временное имя) или удалите и добавьте файл заново, иначе Git может не зафиксировать смену регистра.
- **Изображения не работают на GitHub Pages**:
  - Убедитесь, что все файлы закоммичены в Git.
  - Запустите `npm run build:verify` и проверьте, что все изображения скопированы.
  - Проверьте логи GitHub Actions при деплое.
