## Зачем этот отдел существует

Документация в этом проекте — это **рабочий инструмент**, а не архив. Каждый агент начинает свою работу с чтения Memory Bank. Если документация устарела:
- Агенты перереализовывают уже сделанные вещи
- Агенты используют мёртвые API/паттерны
- Код ломается потому что агент начал писать "по доке" которая врёт

**Твоя задача:** поддерживать документацию в состоянии, когда любой новый агент может прочитать Memory Bank и за 5 минут получить точную картину проекта.

## Стандартные операции

### При добавлении нового StorageProvider стора
1. Обновить `tech_context.md` — добавить ключ в список сторов, обновить счётчик
2. Обновить `backend/storage/__init__.py` — добавить ключ в docstring
3. Обновить `SUPABASE_SCHEMA_AND_MIGRATION.md` — добавить строку в реестр миграций
4. Если стор связан с новой механикой — обновить `product_logic.md`

### При добавлении нового API эндпоинта
1. Обновить `tech_context.md` — добавить контракт (метод, путь, auth, тело, ответы)
2. Если эндпоинт принадлежит новому домену — добавить секцию в `BACKEND_CONTRACT_GUARD.md`

### При изменении стека (зависимости, Node/Python версии)
1. `tech_context.md` строка 4 — версии стека
2. `GEMINI.md` § Tech Stack
3. `README.md` § Spaceship UI и Prerequisites
4. `active_context.md` — если мажорное изменение

### При добавлении новой роли
1. `src/types/authRole.ts` — код (source of truth)
2. `product_logic.md` — таблица ролей
3. `ARCHITECTURE_AND_RESOURCES.md` — таблица ролей и панелей ЛК
4. `tech_context.md` строка 93 — список ролей

### При завершении спринта / крупной задачи
1. `progress.md` — добавить запись в соответствующий раздел
2. `active_context.md` — обновить Current Focus
3. `ROADMAP_2026.md` — пометить задачу как Done (если она там есть)
4. `agent-sync.md` — handoff запись для следующих агентов

## Связь с другими отделами

- **Архитектура / Backend:** Когда они добавляют сторы, эндпоинты, миграции → тебе нужно обновить docs
- **Frontend / UX:** Когда меняются панели ЛК, роли, компоненты → обновить ARCHITECTURE_AND_RESOURCES
- **DevOps / Infra:** Когда меняется деплой, env vars, URLs → обновить tech_context + ARCHITECTURE
- **Продукт:** Когда добавляются игровые циклы, механики → обновить product_logic

**Правило:** после каждого PR/деплоя спрашивай себя: "Нужно ли обновить Memory Bank?"
