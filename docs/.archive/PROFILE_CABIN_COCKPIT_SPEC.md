## 1) Цель

Сделать **десктопную** версию ЛК в формате **кабины корабля**:

- Внизу экрана **всегда** фиксированная консоль (терминал по центру).
- Слева от терминала — **3** крупные кнопки.
- Справа — **3–4** крупные кнопки.
- Консоль = главная навигация по функциям ЛК.
- В «белой зоне» (main viewport) открываются **экраны/панели**: обзор, вкладки, дашборды, шеринг, чат и т.д.
- Почти везде — **прогресс-индикаторы**, привязанные к уже существующим данным (не вводим новые сущности).

> Важно: это **перевёрстка**, а не новая продуктовая логика. Никаких новых API, новых сущностей, новых «механик» — только представление и удобная навигация по тому, что уже есть.

## 3) UX-модель кабины (как это работает)

### 3.1 Всегда есть 3 слоя
1) **TOP BAR** (системный): Назад / Подсказки / Редактировать
2) **BACKUP STRIP** (системный): экспорт/импорт/lastUpdated
3) **MAIN VIEWPORT** (экран): панели/дашборды/вкладки
4) **BOTTOM CONSOLE** (пульт): фиксированный, поверх, центрированный

### 3.2 Два режима в main viewport
- **Режим "Обзор"**: сетка/компоновка панелей (дашборды) как «раскрытая кабина».
- **Режим "Экран функции"**: выбранная функция (вкладка или конкретный дашборд) получает больше места.
  - MVP: достаточно «фокуса» через скролл/подсветку.
  - v1: по кнопке «Развернуть» — оверлей/большой экран (без потери логики, переиспользуем те же компоненты).

### 3.3 Пульт = навигация по ВСЕМ функциям
Ограничение по железу: 3 кнопки слева + 3–4 справа.
Поэтому делаем так:

- **Главные кнопки** переключают "режим/раздел".
- Терминал по центру может показывать "контекст" (что открыто) и **второй уровень** (короткие кнопки/иконки для прыжков к конкретным панелям) — но **без новых функций**, только навигация/скролл/переключение вкладок.

## 5) Нижняя консоль: структура DOM (MVP)

> Консоль добавляем в разметку ProfileView, но в базовом профиле она **display:none**, а в spaceship — включается.

Рекомендуемая структура (нейтральная, без ломания существующих классов):

- `.profile-view-console` (fixed bottom)
  - `.console-cluster.console-cluster--left` (3 кнопки)
  - `.console-terminal` (рамка терминала, центр)
  - `.console-cluster.console-cluster--right` (3–4 кнопки)

Каждая "крупная кнопка":
- иконка (существующая или svg)
- label (короткий)
- мини-индикатор прогресса (полоска/дуга/точки) — **из существующих данных** или скрыт, если данных нет.

### 5.1 Маппинг кнопок пульта (MVP: только навигация)
ЛЕВАЯ ТРОЙКА:
1) **Обзор** — скролл к началу/фокус панели дашбордов
2) **Путь** — `setActiveTab('active')` + скролл к секции вкладок
3) **Команда** — скролл к `#team-dashboard`

ПРАВАЯ ГРУППА:
1) **Коллекция** — `setActiveTab('collection')` + скролл
2) **Журнал** — `setActiveTab('journal')` + скролл
3) **Мастерская** — `setActiveTab('workshop')` + скролл
4) (опционально, если 4 кнопки) **Связь** — скролл к `#profile-share-center` и/или `#profile-chat-trigger`

> Это уже даёт "пульт", не добавляя новых функций: только управление тем, что уже существует.

### 5.2 Терминал (центр) — без новых функций
MVP: терминал показывает:
- текущий раздел (например: «Экран: Журнал»)
- короткую подсказку (если включён HintOverlay)
- "софт-кнопки" второго уровня (v1) — **только навигация**:
  - прыжки к панелям (Инспектор / 4K / Совет / Дневник / Бро / Крыло)

## 8) Progress-индикаторы (как считать без новых данных)

Главный прогресс (XP/уровень) остаётся в паспорте (как сейчас).
Модульный прогресс (на кнопках пульта и на панелях) берём из существующего:

- Инспектор: `Tasks: done/total` уже есть в компоненте
- Команда: состояние команды (есть/нет), прогресс задач (если есть)
- Коллекция: кол-во достигнутых / всего (если есть в progress) или скрыть индикатор
- Журнал: кол-во записей achievedSorted
- Мастерская: доступ (locked/unlocked) + активность (customBadges count)
- Шеринг/чат: просто "статус" (on/off), без процентов

Правило: если нет надёжного источника — индикатор скрыть (не рисовать фейковые проценты).

## 9) План реализации (чтобы агент начал быстро)

2) Добавить `.profile-view-console` (DOM)
3) В `profile-view-spaceship.css`:
   - зафиксировать консоль снизу
   - дать контенту bottom padding
   - разложить зоны (top bar / backup / viewport)
   - сделать "панельную" раскладку дашбордов (grid)
4) Привязать кнопки пульта к **существующим** действиям:
   - setActiveTab(...)
   - scrollIntoView по критичным id

### Этап C — v1 (фокус/разворот панелей)
1) "Фокус панели" (подсветка + прокрутка)
