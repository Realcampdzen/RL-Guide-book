# Улучшение дизайна кнопок, меню и прогресс-баров

Краткий гайд по выводам из [ui design deep-research-report.md](ui%20design%20deep-research-report.md) применительно к текущему веб-приложению (React + CSS).

---

## Что в отчёте рекомендуется для веб-кабинета

- **Стек:** React + **Motion (Framer Motion)** + **Tailwind** + **Headless UI** — контроль стиля без навязанного «материала», доступность.
- **Анимации:** Motion — переходы и layout-анимации; **GSAP** — сложные таймлайны и секвенсы.
- **Дизайн-система:** токены (цвет, типографика, отступы 4/8/12/16, радиусы, тени/glow), явные состояния: hover / focus / pressed / disabled.
- **Прогресс-бары:** значение 0…1 + визуальный слой эффекта (пульс, перелив, при желании — маски/частицы). Для «игрового» вида — PixiJS (WebGL), для обычного — SVG/CSS достаточно.

У вас сейчас: **React, чистый CSS** (в т.ч. `profile-view-spaceship.css`), **Radix Dialog**. Tailwind/Motion/Headless UI не используются — ниже предложения работают и без них, с возможностью постепенного внедрения.

---

## 1. Кнопки (buttons)

### Что уже хорошо
- Есть hover/focus (`:hover`, `:focus-visible`) и активное состояние (`.active`).
- Переходы заданы (`transition: transform 0.15s ease, box-shadow …`).
- Используются CSS-переменные (`--cabin-neon-*`, `--console-button-size`).

### Что улучшить по отчёту

**Токены и состояния**
- Ввести явные токены для кнопок в `:root` или `.profile-spaceship-root`:
  - размеры: `--btn-height-sm`, `--btn-height-md`, `--btn-radius`;
  - состояния: `--btn-bg`, `--btn-bg-hover`, `--btn-border-focus`, `--btn-shadow-active`;
  - длительность переходов: `--btn-transition-duration` (например 0.2s).
- Добавить состояние **pressed** (`:active`): лёгкое уменьшение scale или более тёмный фон, чтобы клик ощущался.
- Убедиться, что **disabled** визуально и по `pointer-events` отключён, контраст достаточный для доступности.

**Микро-анимации**
- Лёгкий scale при hover (например `transform: scale(1.02)`) и при active (`scale(0.98)`).
- Если позже добавите **Motion**: можно заменить на `whileHover`/`whileTap` с spring для более «живого» ощущения.

**Пример дополнения в CSS (без новых зависимостей)**

```css
/* Токены кнопок (добавить в .profile-spaceship-root или в общий слой) */
.profile-spaceship-root {
  --btn-transition-duration: 0.2s;
  --btn-radius: 14px;
}

/* Пример: явный :active для «нажатия» */
.profile-spaceship-root .profile-view-cabin-progress-hub .profile-tabs-nav button:active {
  transform: translateX(3px) scale(0.98);
}
```

**Сделано (hub, центральная консоль):** для кнопок табов «В пути / Избранное / Коллекция / Журнал» добавлено состояние **pressed** (`button:active`): десктоп — `transform: translateX(4px) scale(0.98)`, мобильный/планшет (max-width: 1180px) — `transform: scale(0.98)`. Контент вкладок при переключении плавно сменяется через Framer Motion (`AnimatePresence` + `motion.div`, opacity 0.15s).

## 2. Меню и вкладки (tabs / menu)

### Что уже хорошо
- Вкладки с подсветкой активного (`.active`), hover, `::before`/`::after` для декора.
- Тултип через `::after` с `data-label`.
- `focus-visible` для клавиатуры.

### Что улучшить по отчёту

**Переходы между вкладками**
- Отчёт: анимировать не только opacity, но и позицию/масштаб; держать **фиксированную высоту** контента (min-height), чтобы при переключении не «прыгал» layout.
- Сейчас переключение контента, скорее всего, без анимации. Варианты:
  - **Только CSS:** задать контейнеру вкладок `min-height` (или фиксированную высоту), для смены контента использовать короткий `transition: opacity 0.2s` у контента панелей.
  - **С библиотекой:** при добавлении **Motion** — `AnimatePresence` + `layout` для плавной смены вкладок; при **GSAP** — короткий timeline (затухание одной панели, появление другой).

**Единый стиль и доступность**
- Проверить, что у всех таб-кнопок единые отступы (padding), радиусы и размер области нажатия (рекомендуемый минимум ~44px по осям).
- Headless UI в отчёте упомянут для доступных примитивов (focus trap в модалках, клавиатурная навигация по табам). У вас уже есть Radix Dialog; при появлении своих выпадающих меню можно взять Radix Tabs или Dropdown Menu для a11y.

## 3. Прогресс-бары (progress bars)

### Что уже хорошо
- **Инспектор:** градиентная полоса, `box-shadow`, анимация «chase» (`cabin-progress-chase`) по `::after` — уже даёт эффект перелива.
- **Rail (вертикальный):** `--progress-value`, плавное изменение `height` (`transition: height 0.28s ease-out`), цветовые модификаторы (cyan/magenta/orange/purple).
- Учтено `prefers-reduced-motion: reduce` — анимация chase отключается.

### Что улучшить по отчёту

**Визуальная «живость»**
- Отчёт: прогресс-бар опыта с «пульсом», переливом, при желании — искры/частицы.
- У вас уже есть перелив (chase). Можно добавить:
  - **Лёгкий пульс:** на полосу заполнения (`.profile-view-cabin-top-inspector__progress-bar`) добавить `animation` по `box-shadow` или `opacity` (например 0.9 ↔ 1) с длительностью 1.5–2s, только если `prefers-reduced-motion: no-preference`.
  - **Второй слой перелива:** ещё один `::before` с другим градиентом или скоростью, чтобы бар казался объёмнее.

**Интерполяция значений**
- Отчёт: для «live»-баров (часто обновляемые) — не дёргать значение рывками, а **интерполировать** к целевому (lerp/spring). У вас rail уже с `transition: height 0.28s ease-out` — это и есть интерполяция на уровне CSS. Если значение меняется из JS, лучше обновлять одно число (процент), а не заменять элемент — тогда переход по `height` останется плавным.

**Небольшой пример «пульса» для полосы (опционально)**

```css
@keyframes cabin-progress-pulse {
  0%, 100% { opacity: 1; box-shadow: 0 0 16px rgba(var(--cabin-neon-cyan-rgb), 0.34); }
  50%      { opacity: 0.92; box-shadow: 0 0 20px rgba(var(--cabin-neon-cyan-rgb), 0.5); }
}

.profile-spaceship-root .profile-view-cabin-top-inspector__progress-bar {
  animation: cabin-progress-pulse 2s ease-in-out infinite;
}
```

И в `@media (prefers-reduced-motion: reduce)` для этого селектора задать `animation: none`.

## Приоритеты внедрения

| Приоритет | Что сделать |
|-----------|-------------|
| Высокий   | Токены для кнопок (переменные), состояние `:active`, проверка disabled и focus. |
| Высокий   | Фиксированная/min высота контейнера вкладок + короткий переход opacity при смене вкладки. |
| Средний   | Лёгкий пульс или второй слой перелива на прогресс-бар (с учётом reduced-motion). |
| Низкий    | Введение Motion или GSAP для более сложных переходов вкладок и микро-анимаций кнопок. |
| Низкий    | Headless UI/Radix для новых меню и табов — по мере появления новых компонентов. |

## Сводка по отчёту

- **Веб-рекомендация:** React + Motion + Tailwind + Headless UI.
- **Анимации:** Motion для переходов и layout, GSAP для сложных таймлайнов.
- **Паттерны:** плавные переходы вкладок с сохранением контекста (locked height), анимированные прогресс-бары с переливом/пульсом, модалки с focus trap.
- **Дизайн-система:** токены (цвет, типографика, отступы, радиусы, тени), явные состояния компонентов.

Текущая база (CSS-переменные, переходы, chase-анимация, reduced-motion) уже совпадает с духом отчёта. Улучшения сводятся к систематизации токенов, явным состояниям кнопок, плавной смене вкладок и опциональному «пульсу» прогресс-баров.
