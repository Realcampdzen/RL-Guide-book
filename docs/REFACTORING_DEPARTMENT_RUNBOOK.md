## Ваша миссия

В 2026 году архитектура проекта перешла на React 19, TypeScript 6 и Singleton Data Layer. Однако часть легаси-монолитов и JSON-хранилищ до сих пор препятствует масштабированию проекта на бессерверных средах (Vercel) и усложняет поддержку UI.

Вы здесь для того, чтобы безопасно, по хирургически точным методикам (Strangler Fig Pattern) отсекать куски монолита и переводить их в изолированные домены. Ваша задача — **сделать код проще, чище и быстрее**, сохранив 100% его изначальной ценности для пользователей.

## 📝 Очередь Задач (Priority Queue)

Ваша работа разбита на конкретные узлы. Не хватайтесь за всё сразу — берите одну четкую мишень, завершайте её, коммитьте, переходите к следующей.

### 1. Распил `ProfileView.tsx` (Фаза 8+)
- **Проблема:** Файл `src/views/ProfileView.tsx` всё ещё весит > 350 KB, несмотря на завершение первых семи фаз. Скорее всего, внутри остались тяжелые инлайн-компоненты (Отрядный уголок, логика рендеринга слоев, Дневник, модалки).
- **Действие:** Выделите один логический домен внутри `ProfileView.tsx` (например, блок `SquadCornerDashboard`). Создайте строгий интерфейс (`Props`), перенесите логику и JSX в `src/views/profile/components/`. 
- **Требование:** Ни одного изменения UI. Всё должно продолжать работать прозрачно.

### 2. Спасение Движков (StorageProvider Engine Gaps)
- **Проблема:** Механики онлайн-движков (`engine_projects.py` и `initiatives.py`) до сих пор используют сырой файловый I/O `open()/json.dump()`. Vercel Serverless перезапускает контейнеры, и все несохраненные в БД инициативы стираются при деплое.
- **Действие:** Создать миграцию SQL и интегрировать `projects` и `initiatives` в паттерн `StorageProvider` (см. `backend/storage/`). Сохранить обратную совместимость для JSON (`USE_SUPABASE=false`).

### 3. Очистка Мёртвых Зон CSS (Dead CSS Cleanup)
- **Проблема:** В рамках расщепления CSS-монолитов из `profile-view-spaceship.css` вынесли 14 поддоменов. Оригинальный файл похудел, но наверняка содержит кучу устаревших классов вроде `#profile-chat-trigger`, которые больше ни к чему не привязаны.
- **Действие:** Просканируйте код. Если CSS-правило ссылается на класс, удаленный при переносе в доменный CSS (или спрятанный за React.lazy), безопасно вырежьте его.

### 4. Инкапсуляция Контекстов (State Scoping)
- **Проблема:** `<DataProvider>` (преемник God Hook) обрабатывает слишком много доменов одновременно. `AuthContext` или `ProgressContext` могут вызывать лишние ререндеры у подписчиков, которым эти данные не нужны.
- **Действие:** Аудит точек подписки. Там, где доменный компонент может подписываться напрямую на свой хук (например, `useCommunityBadges`), он не должен дергать глобальный Scope всего `ActiveContext`.

## 🚫 Антипаттерны (Чего делать НЕЛЬЗЯ)

1. ❌ **Начинать масштабный перенос без TypeScript проверки на входе.** Вы должны запустить линтер (или `tsc`) ДО рефакторинга, чтобы знать базовое количество ошибок.
2. ❌ **Менять дизайн или бизнес-логику.** Рефакторинг — это изменение внутренней структуры при сохранении 100% внешнего поведения. (Исправление явных UI-багов, появившихся из-за ваших действий, — обязательно).
3. ❌ **Создавать абстракции ради абстракций.** Не плодите пустые обёртки. Не переносите `useState`, который используется несколькими независимыми компонентами, в одного Child'а. Связывайте компоненты строгими `Props`.
4. ❌ **Обновлять статусы завершения без доказательств (Evidence).** Всегда сопровождайте свои pull requests/коммиты ссылками на то, что код компилируется.

2. Обновите **[\.memory-bank/active_context.md](../.memory-bank/active_context.md)** — "Phase 8 of ProfileView extraction complete: SquadCorner isolated."
3. Оставьте запись в **[agent-sync.md](../agent-sync.md)** от лица Отдела Рефакторинга для будущего агента.
4. Отдыхайте, вы спасли проект от Legacy-монстра!
