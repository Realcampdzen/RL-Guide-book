# PLAN_O1_M1_2026-02-25

Стартовый план параллельного спринта:
- **O1 (7–10 дней):** операционка НейроСтёпы
- **M1 (Q1):** scoped engines (движки в контексте camp/shift/squad)

## 1) Цели спринта

### O1 — Operational Layer
- Запустить стабильный контур: SMM + FAQ + objections + ежедневная операционка.
- Снизить хаос в коммуникациях и ускорить ответы в обсуждениях.
- Повысить конверсию в диалог/бронь к старту смены.

### M1 — Product Mechanics (Q1)
- Убрать архитектурный разрыв: Team и Squad не должны жить как несвязанные миры.
- Ввести scope у движков: `camp | shift | squad` + связи `shiftId/squadId`.
- Обеспечить корректное отображение и фильтрацию в UI и API.

---

## 2) O1: backlog на 7–10 дней

1. Зафиксировать SMM runbook как обязательный процесс (done: docs/smm/README + чеклисты).
2. Внедрить ежедневный цикл:
   - утро: подготовка и фактчек,
   - день: комментарии/FAQ,
   - вечер: ретро и патчи шаблонов.
3. Использовать конверсионные пакеты:
   - `LAST_6_SPOTS_COMMENT_PACK.md`
   - `PARENT_OBJECTIONS_HANDLING.md`
4. Вести KPI-лог:
   - replies,
   - входящие вопросы,
   - диалоги по записи,
   - заполнение мест.

### O1 Definition of Done
- 7 дней подряд выполнен дневной цикл без срывов.
- Есть лог улучшений и минимум 1 итерация патча формулировок.
- Зафиксирован прирост по минимум 2 KPI.

---

## 3) M1: технический backlog (Q1 scoped engines)

1. Спецификация модели:
   - поля `scope`, `shiftId`, `squadId` для Team.
2. Backend:
   - обновить storage/schema и API фильтрацию.
   - гарантировать обратную совместимость для существующих Team.
3. Frontend:
   - обновить TeamContext/TeamDashboard.
   - в контексте отряда показывать релевантные движки.
4. Миграция:
   - правила маппинга старых данных в новый scope.
5. Smoke tests:
   - создать scoped движок,
   - вступить/выйти,
   - проверить видимость по ролям и контекстам.

### M1 Definition of Done
- Scope модель работает end-to-end (API + UI + storage).
- Нет деградации существующего user flow.
- Добавлен evidence в ROADMAP/claim/report.

---

## 4) Параллельная работа (чтобы не мешать друг другу)

- O1: docs + процессы + контент-операции (без рискованных backend-ломок).
- M1: код механик + миграция + smoke.
- Синхронизация: 1 короткий daily sync по рискам и блокерам.

---

## 5) Риски и страховки

- Риск: смешение SMM и механик в одном потоке.
  - Страховка: отдельные DoD и отдельные owner-потоки.

- Риск: scope-миграция ломает текущие team-флоу.
  - Страховка: fallback + smoke-test до merge.

- Риск: FAQ уедет от актуальных условий.
  - Страховка: перед публикацией обязательный фактчек переменных данных.
