# NEUROSTEPA_VALUE_FILTER.md

Архитектурный фильтр для заимствований из внешних агентных систем (в т.ч. Agent OS/курсовых моделей).

## 1) MUST ADOPT (берём обязательно)

1. **Повторяемые jobs вместо ручного героизма**
   - Каждая регулярная задача оформляется как процесс с входом/выходом/DoD.

2. **Skills как SOP-процессы**
   - Не «умный промпт», а минимальная операционная инструкция с чётким результатом.

3. **Markdown-first память и отчётность**
   - Решения, изменения, итоги и next step фиксируются в .md.

4. **Цикл улучшений по факту выполнения**
   - После каждого цикла: что сработало / что нет / какой патч процесса.

5. **Ролевое разделение контуров**
   - Participant / Parent / Counselor / Shift leader / SMM имеют разные сценарии и правила.

## 2) ADAPT (берём с адаптацией под Реальный Лагерь)

1. **Канбан/доски задач**
   - Нужны, но в лёгком виде (md-борд + claim board), без тяжёлого PM-overhead.

2. **Контентные пайплайны**
   - Идея → формулировка → публикация → обсуждение → ретро, но с лагерным тоном и этикой.

3. **Автономность агентов**
   - Нужна в рамках guardrails (факты, цены, юридические ограничения, эскалация).

4. **Стандарты/инъекция стандартов**
   - Внедрять поэтапно: сначала SMM/FAQ/approval, потом глубже в механики ЛК.

## 3) IGNORE (сознательно не берём сейчас)

1. **Инструментоцентричный фанатизм**
   - Не копируем чужой стек 1:1, берём принципы.

2. **Контент-воронку под инфобиз-модель**
   - У нас другой продукт: лагерь и образовательная среда.

3. **Переусложнение ролей и оргструктуры на старте**
   - Сначала операционная устойчивость, затем масштабирование структуры.

4. **Ранний enterprise-overengineering**
   - Метрики и процессы нужны, но без бюрократии ради бюрократии.

## 4) Архитектурный принцип для команды

**Берём не “как у него”, а “что работает у нас”.**

Критерий внедрения любой практики:
- ускоряет ли это полезную работу,
- снижает ли хаос,
- улучшает ли опыт ребёнка/родителя/вожатого,
- не ломает ли продуктовую философию Реального Лагеря.
