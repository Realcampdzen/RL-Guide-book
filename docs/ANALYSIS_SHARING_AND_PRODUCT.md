# Анализ: шеринг, всплывашка и продуктовость Путеводителя

Подробный отчёт по текущему состоянию репозитория, тексту всплывашки на главном экране, привязке шеринга в соцсети, сценарию «избранное → рилс/пост», дополнительным идеям и учёту ограничений (РФ, GitHub Pages, перспектива ЛК). Документ предназначен для разработчиков и продукта.

---

## 1. Текущее состояние репозитория и плана

### 1.1. Единый источник истины

**WORKFLOW_GAME_CONCEPT_PLAN.md** — мастер-документ проекта. В нём зафиксированы:

- Выводы агентов A–E (данные, UX, НейроВалюша, смыслы Реального Лагеря, ограничения GitHub Pages).
- Product Map: сущности (категория, значок, уровень, прогресс), роли, сценарии, UX-точки интеграции.
- MVP: прогресс по уровням (`N.X.Y`), localStorage, экспорт/импорт JSON, без бэкенда.
- Схема данных прогресса, правила статусов, копирайт по экранам, карта UX-вставок, риски и бэклог.

Все изменения плана и новые решения вносятся через этот файл; код при реализации ориентируется на него.

### 1.2. Серверы и окружения

- **Staging (основная разработка):** `npm run dev` → порт **3001** (vite.config.ts). Base path `/RL-Guide-book/`, proxy на API 4000. URL: `http://localhost:3001/RL-Guide-book/`.
- **Изолированная фича (мобильная игра / прогресс):** порт **3005** (DEV_ISOLATED_GUIDE.md). Запуск: `npx vite --port 3005 --host` или `npm run dev -- --port 3005 --host`. Используется, чтобы не конфликтовать с 3001, 3002, 4000, 8000. URL: `http://localhost:3005/RL-Guide-book/`.
- **Деплой:** GitHub Pages по push в `main` (workflow `.github/workflows/deploy-simple.yml`). Сборка: `npm run build`, артефакт — `dist`. Бэкенда на хосте нет.

### 1.3. Реализованный прогресс и избранное

- **Прогресс не сбрасывается при закрытии приложения:** ключ в localStorage `rl_guide_progress_v1`, схема с `progress`, `favorites`, `profile`, `meta` (ProgressContext.tsx, useUserProgress, типы в userProgress.ts).
- **Интеграция:** ProfileView (личный кабинет), BadgeLevelView (фиксация уровня, рефлексия), CategoryView (чипы прогресса), BadgeView (статус, «В мой путь»). Избранное: `toggleFavorite(favoriteId)` в контексте; кнопка «В избранное»/«Убрать из избранного» в BadgeLevelView и таб «Избранное» в ProfileView.

Итог: база для тестирования игрового опыта детьми и родителями уже есть — прогресс и избранное хранятся в localStorage и переживают закрытие вкладки.

## 2. Разбор текста всплывашки на главном экране

### 2.1. Где находится

**Файл:** `src/components/BlueNestLanding.tsx`.

- **Триггер:** клик по кнопке в подзаголовке «Здесь вы найдете 242 значка в 14 категориях» (строка ~363). Кнопка имеет `aria-haspopup="dialog"`.
- **Диалог:** при `isConceptOpen === true` рендерится через `createPortal` в `document.body` блок с `role="dialog"` и `aria-label="О концепции игры"` (строка ~537–591).

### 2.2. Содержимое всплывашки (цитата)

- **Заголовок:** «Игра, которая развивает участников и Лагерь».
- **Абзацы:**
  - В Реальном Лагере ребята становятся организаторами и развивают 4К навыки на практике. Запускают проекты, проводят мастер-классы и целые тематические дни. Объединяются в Движки, изучают вожатское мастерство и наполняют программу лагеря живыми традициями.
  - Система «Реальных значков» — это open-source. Её реально адаптировать под любой лагерь и коллективы разной направленности. Создавайте свои значки, категории и локальные мемы.
  - **Ключевая фраза:** «Фиксируйте достижения. **Делитесь ими в соцсетях.** Создавайте команды. Общайтесь с другими игроками. Прокачивайте навыки коллаборации и организации отрядных дел.»
  - Это живая система: она растёт вместе с участниками и меняет реальность лагеря и смены. Игровые механики здесь — инструменты педагогики общей заботы и соуправления.
- **Подпись:** «С наилучшими пожеланиями всем настоящим и будущим Реальным Вожатым, Степан Иванов».

### 2.3. Привязка шеринга к всплывашке

Текст уже обещает «Делитесь ими в соцсетях», но явного действия нет. Рекомендация:

- Добавить в **нижнюю часть диалога** (после последнего абзаца, перед подписью) блок **«Поделиться идеей Путеводителя»**: одна кнопка «Поделиться» или «Рассказать друзьям».
- По нажатию — переход в **общий сценарий шеринга** (единый компонент генерации картинки 16:9/9:16 и Native Share / скачивание). Логику не дублировать: одна механика, три точки входа (всплывашка, избранное/успех уровня, личный кабинет).

## 3. Сценарий «Избранное → рилс/пост»

### 3.1. Пользовательское действие

1. Пользователь на экране значка/уровня нажимает «Добавить в избранное» (или уже добавил).
2. После добавления (или сразу после клика) показывается необязательный шаг: «Создать картинку для соцсетей?» с кнопкой «Сделать рилс/пост».
3. Переход в общий компонент генерации изображения.

### 3.2. Форматы 16:9 и 9:16

- Один и тот же состав: фон (космос/лагерь), интерфейс/лого, название значка и категории, короткий текст.
- **16:9** — для поста (лента ВК, Telegram и т.д.).
- **9:16** — для сториз/рилсов (мобильный приоритет). На мобильных по умолчанию предлагать 9:16 и Native Share API.

### 3.3. Источники текста

- **MVP:** шаблонные фразы из ai-data (например `description` значка, название категории). Без вызова ИИ.
- **Пост-MVP:** опционально короткий ИИ-текст (подпись, мотивация) через существующий чат/API или отдельный лёгкий запрос.

### 3.4. Мастер-класс в лагере

Сценарий для вожатого/педагога: «Показать значок → добавить в избранное → нажать «Сделать рилс» → получить картинку → выложить в соцсети». Укладывается в одну и ту же механику. Во всплывашке на главной можно добавить короткую подпись: «На мастер-классе можно за минуту сделать рилс про свой маршрут».

## 4. Две дополнительные идеи

### 4.1. «Старт маршрута» как первый пост

При **первом** нажатии «В мой путь» по значку показывать короткий экран: «Ты выбрал маршрут [название]. Хочешь зафиксировать старт и поделиться?» с превью одной картинки: «Я начал путь к [значку] в Путеводителе Реального Лагеря» в форматах 9:16/16:9. Это даёт «скрин начала действия» и повод для поста/рилса без ИИ на первом шаге и усиливает идею «старт прогресса как контент».

### 4.2. «Чекпоинт недели»

Раз в неделю (или за смену) в личном кабинете показывать карточку: «Чекпоинт: что было главным на этой неделе?» — пользователь выбирает один уровень или одну короткую заметку. Результат сохраняется только локально; опционально экспорт в «картинку недели» для шеринга. Даёт ритм, рефлексию и один предсказуемый повод для поста без соревновательности и без бэкенда.

## 5. Ограничения и продукт

### 5.1. GitHub Pages и Cloudflare

- Всё остаётся статикой и клиентом; генерация картинок и шаблонные тексты — на клиенте. API чата/нейросети при необходимости — уже есть proxy на 4000, в проде — внешний endpoint. Cloudflare можно подключать для CDN/DDoS без изменения логики шеринга.

### 5.2. Законодательство РФ и персональные данные

- Не хранить в приложении персональные данные детей (телефон, почта, ФИО) без согласия и без полноценного личного кабинета с авторизацией.
- Генерация картинок и шаблонные подписи не являются персональными данными. Явно не собирать данные для соцсетей на своей стороне — только «картинка уходит в устройство пользователя / Native Share».

### 5.3. Будущее приложение (ЛК, авторизация)

- План уже предполагает роли (игрок, куратор, админ) и пост-MVP синхронизацию. Варианты входа: родитель, участник смены, путешественник (свободное изучение без бота и клиентских фишек).
- Шеринг заложить так: в MVP «картинка/рилс» не привязаны к аккаунту; после появления авторизации можно добавить «сохранить в мои посты» или «отправить куратору» без изменения формата картинки. Единый контракт: «создать изображение 16:9/9:16 + отдать Share/download».
