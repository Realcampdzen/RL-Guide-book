# 📜 Спецификация: Режим Бога (Presenter Mode / Super-View)

## 1. Контекст и Бизнес-Ценность (Why?)
Во время публичных презентаций платформы или записи видео-демо "Путеводителя", разработчик/СЕО сталкивается с проблемой: демонстрация на продакшен-базе может привести к случайному созданию отрядов, рассылке пушей или порче реальных данных. 
Нужен безопасный режим-песочница ("Режим Бога"), который позволит разработчику визуально получать доступ ко всем кабинетам, отрядам и движкам, а также "симулировать" любые действия (создания, согласования), не записывая ничего в базу данных.

## 2. Использование (User Stories)
- **Сценарий 1 (Безопасность записи):** Как Разработчик, я хочу нажать кнопку "Включить God Mode", чтобы все мои POST/PUT/DELETE запросы перехватывались в браузере и возвращали успешный фейковый статус (200 OK) вместо реальной записи в БД.
- **Сценарий 2 (Просмотр Движков):** Как Разработчик с включенным God Mode, я хочу открыть панель "Мои Движки" и увидеть список *всех* движков лагеря, имея возможность войти в любой из них как полноправный участник.
- **Сценарий 3 (Просмотр Отрядов):** Как Разработчик при включенном God Mode, находясь на экране "Вступить по коду", я хочу видеть список всех отрядов из всех смен, и иметь возможность "виртуально" в них вступить по нажатию кнопки.

## 3. Бизнес-Логика и Ограничения (Business Rules & RBAC)
- **Активация:** Режим доступен *только* на клиенте через введение секретной команды в паттернах логов или через 5 тапов по аватарке в верхнем углу (настройки `localStorage.setItem('rl_god_mode', 'true')`).
- **Индикация:** При включении должна всегда гореть желтая плашка "🟡 PRESENTER MODE".
- **Безопасность БД:** Ни один `POST`, `PUT`, `PATCH`, `DELETE` запрос кроме `POST /api/generate` (для генерации ИИ, так как это Read-смысл) не должен доходить до реального Backend API. 
- **Ограничения:** Изменения, сделанные во время сессии, не сохранятся при обновлении страницы (фейковые состояния кешируются локально).

## 4. Контракты Данных (Tech Architecture)
**(Заполнено Agent Gamma / Архитектор)**
- Точка интеграции: Прямо внутри `window.fetch` (Interceptor паттерн). Файл: `src/utils/godModeInterceptor.ts`.
- **API `GET /api/teams/mine`**: Перехватывается и заменяется вызовом `GET /api/teams`. Пост-обработка добавляет текущий `deviceId` в `team.members` каждого движка.
- **API `POST /api/squads/:id/join`**: Возвращает Mock-одобрение и сохраняет выбранный `squadId` в `localStorage.getItem('rl_god_mode_squad')`.
- **API `GET /api/squads/mine`**: Возвращает сформированный `SquadMineResponse`, базирующийся на сфабрикованной структуре на основе `rl_god_mode_squad`.
- **UI Bypass List**: В `SquadCabinetPanel.tsx` добавляется логика вызова `GET /api/shifts` с последующим вызовом множественных `GET /api/shifts/:id/squads` для формирования списка кнопок "Виртуального вступления".

## 5. Критерии Приемки (Acceptance Criteria - DoD)
- [x] В консоли срабатывает `__enableGodMode__()` и включается плашка.
- [x] При создании "демо-расписания" интерфейс моргает `SUCCESS`, но если выключить режим и перезагрузить, БД остается чистой.
- [x] Во вкладке "Движки" показывается полный список, а не только личные.
- [x] Во вкладке "Отряд" появляется золотая панель со списком всех отрядов и смен.
- [x] Вступление в отряд происходит бесшовно (без ошибок).
